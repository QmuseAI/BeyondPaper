BeyondPaper｜论文之后

把论文在压缩中丢掉的东西找回来

一个跑在 SciencePal 上的研究解剖智能体：执行 · 查错 · 找回 · 追问

问题

论文是有损压缩

读者拿到的只是结果。丢掉的部分决定了这个结果能不能信、在什么条件下会失效：

  • 失败的分析路径和负结果
  • 没写出来的条件和选择
  • 写进去但前后对不上的数字
  • 文字说一套、代码做一套

下一个研究者通常要花几周重新踩一遍这些坑。

BeyondPaper｜论文之后2
思路

BeyondPaper 做四件事输入：论文 + 作者公开的代码和数据。输出：带证据的结论台账、问题清单、失败路径、给审稿人和尽调者的一页纸、一个能追问的论文智能体。

执行

让论文跑起来

在沙盒里重跑作者代码，结果先和作者自己的存档输出对照（复现门），再拿来评判论文。

查错

文字、数字、代码、数据

统计量重算、数字前后对照、Methods 对代码、测试集是否被用来选模型、文件是否写错。

找回

论文没写的

换一个合理的分析选择结论还在不在（多重宇宙）；隐藏条件；导出失败路径；同类论文里真出过的错（前车之鉴）。

追问

下一步做什么

把整篇论文变成一个经过测试的智能体，可以问 "what if"；按信息增益排出下一步实验。

查错 · 代码与数据

只读文字查不到的错，藏在代码和数据文件里v1.7 起由确定性脚本扫描，模型负责逐条确认或降级。

test_set_reuse

用测试集拟合或挑选模型（上一页第 2 条）。

split_overlap

测试集的行出现在训练/发现集文件里（上一页第 4 条）。

stale_loop_variable

循环结束后还在用循环变量，只取到最后一次的值。例：一篇 meta 分析的 funnel.R:17。

duplicate_output

同一个对象存成两个名字不同的文件（上一页第 3 条）。

BeyondPaper｜论文之后7
追问

经过审计的论文智能体Paper2Agent（Miao et al., Nature 2026）把论文变成可调用的工具；作者自己指出，它衡量的是 "faithful execution rather than analytical validity"。BeyondPaper 补上后一半。

工具开放前先测试

  • T1 结论、发现、失败路径都能读出
  • T2 默认参数重跑 = 记录的基线（相对误差 1e-4）
  • T3 两次重跑结果相同
  • T4 已知的"破坏性改动"确实会翻转结论

T2、T3 不通过，reproduce/whatif 不开放。每个回答都带上结论灯号、复现等级和失效条件。

# Chen 2024，v1.11.16，在 SciencePal 里追问 > reproduce 9/9 个输出 = 记录的基线 > whatif alpha=0.02 外部敏感度 0.683 → 0.921 > whatif k=15 外部敏感度 0.683 → 0.667（几乎不变） 注意：主结论只在 37% 的分析组合里成立； 发现集包含全部 142 个测试样本

把 L1 惩罚从代码里的 0.005 改成 0.02，智能体真的重跑分析，而不是凭记忆回答。翻转结论的 what-if 会被写成新发现。

BeyondPaper｜论文之后13
三种读者

同一份分析，给审稿人、编辑和尽调者的一页纸build_brief.py --audience investor | reviewer | editor：只重新组织本次运行的文件，不加新的判断。

一页纸上有什么

  1. 总体灯号、复现等级、多重宇宙稳健性
  2. 主要结论各自的灯号和依据
  3. 结论在什么条件下不成立
  4. 要对方补充的材料
  5. 要作者回答的 5 个问题
  6. 最能降低不确定性的验证

尽调版只说证据是否支撑结论，不评价商业价值；也不用直接面向作者"挑错"。

示例问题（Chen 等 2024 的已核实问题）

  1. 最终模型的 10 个特征是在哪些样本上选出来的？discovery_set.xlsx 是否包含测试样本？
  2. 预后模型的特征数 28 是按哪个数据集的 c-index 选的？
  3. 外部测试集的预测文件为什么与测试集文件完全相同？
  4. 报告的 "95% CI" 是 2.5/97.5 还是 5/95 分位？
  5. L1 系数是 0.01 还是代码里的 0.005？
BeyondPaper｜论文之后14
局限

现在做不到的

  • 模型不稳定，结果就不稳定。模型稳定（全程 DeepSeek V4 Pro）时 BeyondPaper 表现很好；SciencePal 会在回合中途把 V4 Pro 换成 V4 Flash 或 GLM，有时没有提示，换来换去时每次结果都有一点偏差（v1.11.16 被换到 Flash 的两次运行各有 1 条红色误报，稳定的重跑没有；更早同一篇注入版 Flash 0/4、Pro 3/4）。要盯着运行，被换就改回 Pro 接着跑。
  • 仍有漏报和误报：v1.11.16 在已知的 34 处真实问题里找到 26 处（漏了 Campbell、Thibault 的几处），盲测有 3 条黄色误报。对外公布任何一条之前，都要人工核实。
  • 样本还小：改进是看着 5 篇测评论文和 6 篇盲测论文写的；最终结果每篇只取一次运行。
  • 一次完整运行 10–60 分钟，平台会中断回合；结果以 bp_out 文件为准。现场只演示追问和结果页。
  • 沙盒没有 R：R 代码靠 Python 移植，复现门兜底，多重宇宙在 R 论文上常常只能跑小规模。
  • 只能处理公开了代码和数据的论文；只有 PDF 时，只做文字层面的检查。
