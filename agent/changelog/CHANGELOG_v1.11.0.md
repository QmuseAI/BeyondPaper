# BeyondPaper v1.11.0（2026-11-17）

目标：修掉 v1.10.5 独立检验里暴露的三类问题——黄灯误报多、单次运行不稳定、平台相关的假消息和死循环。

## 1. 黄灯误报：手写发现必须先过执行核对

- **新阶段 6a 核对**（`bp-relay-package/scripts/verify_queue.py`）。每条智能体手写的红/黄灯，都要在 `verify.json` 里记录一条实际执行过的命令、输出文件和结论（upheld / refuted / weakened）。比较两个数时，要写出两边的 dataset、metric、endpoint、population、split、table。`build_passport.py` 只保留核对通过的手写红/黄灯，其余降为灰灯，并附上原因。
- **20 条可回放的复核规则**（`build_passport.py` v111_caps），每条都来自一条人工判定的误报：
  - 比较对象不对：不同数据集、不同指标；证据自己写明"不是同一个量"；一方是我们自己的移植值。
  - 作者材料里已有答案：所问的细节作者文件里就有；所说"缺失"的列其实存在。
  - 统计或计数算错：单变量模型套用每变量事件数（EPV）；Welch 自由度其实一致；混淆矩阵重数一致；存档样本数多于所说的子集；按数据重数并不存在完全分离；子组之和等于总数。
  - 认错了表或代码：存档里打印的是另一张表；按代码追踪，检验的变量数与存档一致。
  - 与论文本身无关：标出的是智能体自己写的文件；Dockerfile 已固定依赖；多重宇宙换的是终点本身；按行号构造的伪分组；方法写明用图形界面工具；清单条目在代码里没有对应位置。
- `numbers_crosscheck.py`：存档文件里别处出现论文值时（只看有区分度的数），判为取错格子，标灰。
- 去重：同一文件的两种路径前缀合并；清单 M1 与手写的"无种子"并入 seed_missing。

## 2. 不稳定：以前时有时无的问题改成脚本必报

新增 `bp-ghost-variables/scripts/deep_checks.py`，写出 `deep.findings.json` 和 `code_facts.json`：

- R/Rmd 列追踪：从 `read.csv` 到列删除、`colnames`、下标切片、模型公式，报告从未进入模型的列（B13：Age、Gender）。
- 治疗后才观察到的变量被当作生存模型的基线预测因子（B13：最佳疗效、毒性分级）。
- Rmd 里算了但没打印、没写出的结果，以及每个 knit 输出实际存了哪张表（B13：只有 pfs_results，os_results 没存）。
- 每个二分类协变量的事件数和删失数（用于核对完全分离的说法）。
- 脚本里手敲的逐折数组，与别处画出的汇总值对比（B12：92.76 对 93.10）。
- 入口脚本从未调用的训练脚本（B12：SGRU_GRU_Kfold.py）。
- 同名指标的定义不一致：宏平均对比单类二分类（B12）。
- 存档权重的层大小与论文写的网络结构对比。不需要安装 TensorFlow 就能解析 checkpoint（B14：4-5-7-1 对 4-6-1）。
- 代码里的超参数与论文值对比，跳过函数签名里的默认值（B14：λ 0.002 对 0.02；Chen：alpha 0.005 对 L1 0.01）。
- 用存档里的计数重算混淆矩阵。

失败机制库新增 5 个论文机制和 2 个审计方机制，以及 10 个案例。同一篇论文自己的案例会按 capsule 编号隐藏，不会泄漏答案。
